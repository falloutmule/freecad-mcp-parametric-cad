# Durable interfaces and controlled iteration

Use for multi-revision projects or topology drift—not every bracket.

Keep source/occurrence inventory, registered interface, knowledge, artifact purpose, applicable requirements and fabrication profile separate. Historical solids are evidence, not automatic ancestors. Interfaces describe contact, axes and empty volumes, not old outlines, pocket shelves or marks.

Knowledge classes: `PHYSICAL_FACT`, `KNOWN_BAD`, `DESIGN_TARGET`, `RETIRED`. Rejecting a model must not erase physical evidence or promote targets into laws.

## Architecture and parameters

When comparable iteration matters, declare structural systems, feature graph, service order, topology invariants and named parameters. Parameters have units, classification, baseline, justified bounds where known and declared consumers. Fixed means not tunable in this phase—not physically verified.

Ordinary corrections change parameters only. Perturb active parameters, measure their intended effects/downstream validity, then restore and reverify the selected state. Remove or mark ineffective, duplicated, derived and target-only values. Prove a protected-geometry conflict before declaring architecture unsatisfiable; optimizer failure alone is not proof.

Declare native dependency graph or explicit external generator/state files as regeneration authority. Scripts can build native editable features. External snapshots identify generator/imported code, inputs/architecture/parameters, runtime and export settings. No session globals, undeclared caches, in-memory-only sources or sliced-source `exec`. Never patch exported STEP.

## Continuous work and context

For authorized straight-through work: generate → existing checks → permitted correction → reverify → requested exports/fabrication preparation → physical handoff. No approval at every arrow. Broken tools/unknown operands require repair, not design changes. Deliver the reopened selected state, not a perturbation or earlier candidate.

Read assembly guidance for complete context. Refresh/quarantine stale hashes, diagnostic objects, status text, labels, placements and measurements when replacing candidates. Reopen before calling context current; contradictions make affected claims unverified.

Deterministic reproducibility is a separate claim: two independently started clean-process builds from one dependency manifest, with reopened disk artifacts compared semantically. Matching bytes alone is insufficient. Do not impose this release exercise on every local edit.

Physical results promote exercised features only. A failed mark does not justify discarding a passed interface. Keep production/motion gates closed where they depend on unresolved physical placement.
